Status: early prototype

Open Journalist is a prototype from November 2026. Do not use it with real research material yet. While the repository is private, downloads and source code need a GitHub account with access to it.

Requirements

  • Windows on x64, or macOS on Apple silicon. Intel Macs are not covered by the packaged build.
  • No administrator rights are needed.
  • For the model features: access to a language model with an OpenAI-compatible API, for example your organization's own inference, a European provider or a local server. The local features (table analysis, findings, file previews) work without one.
  • To run from the source code: Git, Python 3.11 or later and Node.js 22 with npm.

Install a packaged build

Builds are made by hand from main and published as releases. The newest is marked Latest.

Windows x64 (.zip) macOS Apple silicon (.dmg)

The builds are not signed yet, so both operating systems warn at the first start.

  1. Unpack OpenJournalist-windows-x64.zip into a folder of your choice, for example under Documents.
  2. Open the folder OpenJournalist and double-click OpenJournalist.exe. Keep the folder _internal next to it.
  3. SmartScreen: if Windows shows “Windows protected your PC”, choose More info, then Run anyway.
  4. The window uses the Microsoft Edge WebView2 runtime. If no window can be created, Open Journalist opens your browser instead.
  1. Open OpenJournalist-macos-arm64.dmg and drag OpenJournalist onto Applications.
  2. Gatekeeper: the app is neither signed nor notarized, so macOS refuses to open it the first time. Open System Settings → Privacy & Security, scroll to the message about OpenJournalist, choose Open Anyway and confirm.
  3. If macOS reports the app as damaged, remove the quarantine mark in Terminal and open it again: 
    xattr -dr com.apple.quarantine /Applications/OpenJournalist.app

Run it from the source code

This is the usual way during the prototype phase. One command sets everything up, builds the interface and opens Open Journalist in your browser. The first start takes a few minutes.

git clone https://github.com/open-journalist/open-journalist.git
cd open-journalist
start.bat
git clone https://github.com/open-journalist/open-journalist.git
cd open-journalist
./start.sh

On macOS, ./packaging/macos/install-dock-app.sh adds an Open Journalist app to ~/Applications that you can keep in the Dock.

The start script creates a virtual environment in .venv, installs the core and builds the user interface. On the branch main, every start first fetches the newest state from GitHub (fast-forward only), so the same command always runs the newest version. Offline or with local changes in the way, the current version starts.

--demo
Puts the demo case “E-Auto-Check (Demo)” into your working store first. See the worked example.
--selftest
Checks the installation and exits.
OJ_NO_UPDATE=1
Skips the update check, for example OJ_NO_UPDATE=1 ./start.sh; on Windows set OJ_NO_UPDATE=1 before start.bat.

Connect a model

Open Journalist has no model built in and sends nothing until you configure an endpoint. Open Settings → Models and add one:

  1. Base URL of an OpenAI-compatible API, and the model name: pick it from the endpoint's model list or type it.
  2. The API key. It goes straight to the credential store of your operating system (Windows Credential Manager or macOS Keychain) and is never written to a file or a log.
  3. The allowed sensitivity classes. A new API endpoint may receive T2 and public by default. T0 is never sent to an API.
  4. Press Test connection. It sends two short synthetic prompts, never your material.

Under Settings → Privacy you can see for each class which endpoint would receive it, and every request that was refused.

Check the installation

--selftest checks every module and dependency, the working store, the files of the interface and the local server, without opening a window and without touching your projects. The exit code is 0 only if every check passed.

$p = Start-Process .\OpenJournalist.exe -ArgumentList "--selftest" -Wait -PassThru
$p.ExitCode
Get-Content "$env:LOCALAPPDATA\OpenJournalist\Logs\selftest.log"
/Applications/OpenJournalist.app/Contents/MacOS/OpenJournalist --selftest

Each check prints one line starting with [PASS] or [FAIL]; a failed line names what is missing. The last line is RESULT: PASS or RESULT: FAIL (…).

Log files

PlatformFolder
Windows%LOCALAPPDATA%\OpenJournalist\Logs\
macOS~/Library/Logs/OpenJournalist/
Linux~/.local/state/OpenJournalist/log/

Each start writes one log file; the ten newest are kept. Logs record identifiers, counts and durations, never keys, document texts or names. When an error message ends with a reference such as (Log: 2026-11-24 14:03:27 job:9b1d77aa), name it when you report the problem. Settings shows the log file of the current start, and “Open folder” opens its folder.

Where your data lives

Projects, documents, claims and decisions stay on your computer, outside the program folder. Every uploaded file is kept byte for byte with its SHA-256 hash, which is checked on every read.

PlatformStory dataSettings
Windows%LOCALAPPDATA%\OpenJournalist\%LOCALAPPDATA%\OpenJournalist\settings.json
macOS~/Library/Application Support/OpenJournalist/same folder, settings.json
Linux~/.local/share/OpenJournalist/~/.config/OpenJournalist/settings.json

The environment variables OPENJOURNALIST_DATA_DIR and OPENJOURNALIST_CONFIG_DIR point Open Journalist at other folders, for example a separate folder for a demo.

When something does not work

Run --selftest and send selftest.log together with the newest openjournalist-….log to the team, through an issue. Read the log files before you share them: they contain folder paths, which usually include your user name. Never attach research material.
